## 📖 1. ملخص تنفيذي

وُلد نظام **RASD** من سؤالٍ بسيطٍ وعميق: *كيف نحفظ شهادةَ العين الساهرة من أن تتبدد بين الورق ورسائل التطبيقات؟*

والجواب كان معماريةً برمجية رصينة تجمع شتات الملاحظة الميدانية — الكاميرا، والطابق، ولحظة الرصد، والوصف، والدليل البصري — في سجلٍّ واحدٍ موثّق، تمضي فيه الملاحظة كما يمضي النصُّ في ديوان التحقيق: مسودةً تُحرَّر، ثم شهادةً تُراجَع، ثم حكماً بالقبول أو الردّ معلّلاً، ثم تقريراً يومياً يُصاغ من المقبول وحده، ويُعتمد برقمٍ محفوظ، ويُخرَج في وثيقة A4 لا يختلف فيها الحبر عن المعاينة.

وقد أعدّ هذا النظام وطوّره **طارق عبد الرحمن** لبيئة وزارة الإعلام، على ثلاث ركائز علمية:

* **الصرامة الأمنية:** لا يرى المرء إلا ما خُوّل له، ولا يُنزَّل الدليل إلا بإذنٍ موثّق.
* **ثنائية اللسان:** العربية والإنجليزية واجهةً ومحتوىً، مع فصلٍ منهجي بين الأصل والترجمة كما يُفصل المتن عن الشرح.
* **الاستقلال التشغيلي:** يعمل على الشبكة المحلية والجوال دون سحابةٍ مدفوعة، ويستعين بالذكاء الاصطناعي استعانةَ المستشار لا الحاكم — يقترح، والإنسان يعتمد.

## 🎯 2. الأهداف والنطاق

**الأهداف — خمسُ غاياتٍ كالنجوم الهادية:**

1. 🖋️ توحيد التدوين الميداني وربطه بالدليل البصري (صورةً وفيديو وصوتاً).
2. ⚖️ ضبط ميزان الاعتماد: مسودة، فراجعة، فقبولٌ أو رفضٌ مسبّب، ولا عبثَ بعد القبول.
3. 📄 إصدار تقريرٍ يوميٍّ واحدٍ لكل يوم عملٍ بضوابط زمنية لا تقبل التأويل.
4. 🌐 حفظ الترجمة كما تُحفظ الأمانة: الأصل ثابت، والنسخة المقابلة projection مخزّنة.
5. 📱 إيصال النظام إلى الجيب: PWA قابلٌ للتثبيت، يعمل على الشبكة المحلية بانقطاعٍ أو اتصال.

**النطاق — ما يحتويه البحر وما يذر:**

* ✅ *داخل النطاق:* الملاحظات، الإرسالات العامة، المعرض الموحد، التقارير، الترجمة، الإشعارات، التصدير والطباعة، الملفات والترتيب.
* 🚫 *خارج النطاق:* التعرّف على الوجوه، والتحليل الجنائي للفيديو، والربط المباشر بالكاميرات — فالرصد هنا شهادةُ إنسانٍ يدوّن، لا عينُ آلةٍ تحكم.

**المعضلات وحلولها — على بساط البحث:**

| المعضلة | الحل المعماري |
|---|---|
| تشتت الملاحظات وضياع المتابعة | سجلٌّ مركزي مفهرس بالحالة والتاريخ والطابق والكاميرا والمراقب |
| تناثر المرفقات بلا مرجع | 🖼️ معرضٌ موحد يجمع الدليل مع رابطٍ لأصله |
| روابط مشاركة معقدة زائلة | روابط دائمة أنيقة `/s/...` بصفحة عرضٍ موثّقة الدخول |
| غموض الاعتماد | دورة حياةٍ معلنة وإشعارٌ عند كل تحوّل |
| استنزاف صياغة التقرير للوقت | توليدٌ آلي يقترح، ومراجعةٌ بشرية توجّب، واعتمادٌ مرقّم يوثّق |
| تباين المعاينة عن المطبوع | محرك وثائقٍ واحد: المعاينة هي الطباعة هي الـ PDF |

## 🛡️ 3. الأدوار والصلاحيات

> *كالمكتبة العريقة: لكل قارئٍ رفُّه، ولكل أمينٍ مفتاحه — والسياسات هنا أمناء لا ينامون.*

دوران لا ثالث لهما، وتُطبَّق الصلاحيات مركزياً عبر `Policies` في الويب والـ API معاً، فلا منطقَ مكرراً ولا ثغرةَ اجتهاد.

| الصلاحية | 👁️ مراقب ميداني `monitor` | 🖋️ كاتب تقارير `report_writer` |
|---|:---:|:---:|
| إنشاء ملاحظة | نعم | نعم (ووجهته الأصلية التقارير) |
| رؤية مسودات الآخرين | لا | لا |
| القبول والرفض | لا | نعم |
| تنزيل المرفقات | مشاهدة فقط | نعم — حصرياً |
| إدارة التقارير | المنشور المرئي فقط، بلا مسودات آلية | إنشاء وتعديل ونشر وسحب تقاريره، ورؤية الكل |

**مرايا الرؤية:**

| حالة الملاحظة | المالك | مراقب آخر | الكاتب |
|---|:---:|:---:|:---:|
| مسودة | نعم | لا | لا |
| قيد المراجعة / مرفوضة / مقبولة | نعم | نعم | نعم |

| حالة التقرير | المراقب | الكاتب |
|---|---|---|
| مسودة | لا | نعم (الكل) |
| منشور مرئي | نعم (بلا محتوى AI وبلا سجل المراجعات) | نعم |
| منشور مخفي | لا | نعم |

🔐 **الدرع الأمني:** مصادقة JWT بتوقيع `HMAC-SHA256` مع إبطالٍ مؤقت، وحماية `CSRF`، وفحص النوع الحقيقي `finfo` مع نبذ الامتدادات الخطرة والمزدوجة، وتحديد المعدل على الدخول والتوليد والترجمة، وترويسات `SecurityHeaders`. والمفاتيح (Gemini وVAPID) حبيسة الخادم لا تظهر في سجلٍّ ولا قاعدة.

التفصيل: [`docs/SYSTEM.md`](./docs/SYSTEM.md)

## 🧩 4. المكونات الوظيفية

### 📝 4.1 الملاحظات الميدانية — اللبنة الأولى

> *كل ملاحظةٍ شهادةُ عينٍ: أين، ومتى، وماذا رأت — فإذا وُثّقت حسُنت روايتها.*

* حقولٌ منهجية مفهرسة: `floor_number` و`camera_number` و`observed_at` و`observed_end_at` والوصف.
* قائمةٌ حيّة صامتة عبر `Livewire\NotesList` بلا إعادة تحميل، وترشيحٌ بالحالة والتاريخ والطابق والكاميرا والمراقب.
* مرفقاتٌ بتسمية `UUID` في قرصٍ خاص `storage/app/private/notes/{id}/` — لا رابطَ عام ولا وصولَ مباشر.
* التقاطٌ مباشر من الكاميرا والميكروفون مع بديلٍ يعمل على الشبكات المحلية.
* 🖨️ طباعة A4 رسمية بترويسة الوزارة وترقيم `صفحة X من Y`.
* عند تجاوز حد المرفقات: تُحفظ الملاحظة ويُعلَن الإخفاق الجزئي `attach_partial` — فلا يضيع جهدُ الميدان.

### 📤 4.2 الإرسالات العامة — طريقٌ موازٍ لا يلتقي

مسارٌ مستقل للبلاغات المبسطة: وصفٌ واختيار كتّابٍ عبر `general_submission_report_writer` ومرفقاتٌ اختيارية، وترشيحٌ زمني (اليوم / أمس / 7 / 30 يوماً).

⚠️ **قاعدة ذهبية:** *القبول يقلب الحالة فقط — والإرسالية لا تستحيل ملاحظةً أبداً.* وحقل `general_submission_id` أرشيفٌ للفصل في العرض لا جسرٌ للدمج.

### 🖼️ 4.3 معرض المرفقات الموحد — ذاكرة العيون

صفحة `/gallery` واحدة تجمع شتات الدليل البصري من الملاحظات والإرسالات.

* البنية: `unionAll` بين `Attachment` و`GeneralSubmissionAttachment` ثم تطبيعٌ إلى `kind, mime, size, viewUrl, ...` وترقيم `paginate(24)`.
* ترشيحٌ قابل للطي (كاميرا، طابق، نوع، تاريخ، ترتيب) وثلاثة أنماط عرضٍ تُحفظ محلياً: شبكة، ومدمج، وقائمة.
* 🏷️ شارة مصدرٍ أنيقة على كل بطاقة (ملاحظة / إرسالية) ورابطٌ للأصل. المشاهدة للجميع، والتنزيل للكتّاب وحدهم.
* التفصيل: [`docs/GALLERY.md`](./docs/GALLERY.md)

### 🤖 4.4 التقارير اليومية والذكاء الاصطناعي — حيث يستشير العقلُ الآلةَ ولا يُسلِمها القلم

تقريرٌ واحد لكل يومٍ من المقبول وحده، بتوقيت `Asia/Damascus` الذي لا يقبل المساومة:

```
ملاحظات مقبولة من اليوم ذاته
  ← توليدٌ آلي يقترح JSON منظمة (ملاحظات + توصيات)
  ← مراجعةٌ بشرية تحرّر (لا حفظَ تلقائياً)
  ← اعتمادٌ يوثّق نسخةً مرقمة في report_revisions
  ← وثيقة A4 واحدة: المعاينة = الطباعة = PDF
```

* ⏳ قاعدة اليوم الواحد على مستوى الخادم في `ReportService` — تُرَدّ ملاحظةُ الأمس ولو بفارق دقيقة.
* 🧠 التوليد يوجز الوقائع بصيغة الماضي، ويُبقي التوصيات فارغةً في الهدوء الروتيني بدل الحشو — فالصمتُ هنا بلاغة.
* 🛡️ حرّاس جودةٍ يردّون المخترَق (تسرّب التوصيات، الترقيم الداخلي، صيغة الأمر، التكرار) برسالةٍ عربية وزرِّ إعادة.
* التركيب ثابت عبر `composeContent()` من حقلين فقط (ملخص + توصيات) — لا نصَّ حرٌّ يتسلل.
* 📐 كثافةٌ طباعية ذكية تشدّ التباعد والخط، والنشر محروسٌ من التقادم `stale`، والأوراق الرسمية (1–7) تُملأ بإحداثيات `config/report_sheets.php`.
* رموز الأعطال بالعربية: `AI_DISABLED` و`AI_AUTH` و`AI_RATE_LIMITED` (+مهلة وعدّاد) و`AI_UNAVAILABLE` و`AI_BAD_RESPONSE` و`AI_BUSY` و`AI_VALIDATION`.
* التفصيل: [`docs/REPORTS.md`](./docs/REPORTS.md)

### 🌐 4.5 الترجمة ثنائية اللغة — لسانان لقلبٍ واحد

> *الأصلُ متنٌ لا يُمَس، والترجمةُ شرحٌ يُحفَظ بجانبه — فلا يطغى الفرع على الجذر.*

| الطبقة | الآلية | المصدر |
|---|---|---|
| الواجهة الثابتة | ملفات الترجمة (800+ مفتاح) | `lang/ar` و`lang/en` |
| كشف لغة المصدر | حتمي بلا AI | `SourceLanguage` (النطاق `U+0600–U+06FF`) |
| ترجمة الملاحظات | مهمة خلفية | `content_translations` عبر Gemini |
| ترجمة الصفحة | دفعاتٌ مخزّنة | `DynamicTranslationController` |

التبديل فوري `POST /locale`، والنص المحايد (أرقام ورموز) لا يُترجَم، والحالات معروضة بلغةٍ إنسانية: *جارٍ التجهيز… / الترجمة جاهزة / قيد التحديث / تعذّر التجهيز.*

### 🔔 4.7 المشاركة والإشعارات وتطبيق الويب التقدمي

* 📲 مشاركةٌ لمنتقي جهات الاتصال وروابط دائمة `/s/...` تتكيف مع `SHARE_URL` — والدخول إجباري والتنزيل للكتّاب.
* 🔔 مركز إشعاراتٍ بدرجٍ جانبي وعدّاد، وبثٌّ لحظي `SSE` مع بديلٍ دوري، ودفعٌ فوري `Web Push (VAPID)` حتى والمتصفح مغلق، وتفضيلات صوتٍ تُحفظ تلقائياً.
* 📱 تطبيقٌ تقدمي يُثبَّت ويعمل على `LAN` بلا إنترنت، عربيُّه `RTL` وإنجليزيُّه `LTR`.

### 👤 4.8 الملف الشخصي والترتيب والتوجيه

* الملف: اسمٌ وهاتفٌ سوري موحّد ورقمٌ شخصي وصورةٌ دائرية بحد 10MB — تُعرَض ملفات الآخرين مع إحصاءات القبول.
* 🏆 الترتيب `/ranking` بالأكثر قبولاً أوّلاً — فالتميّز هنا يُقاس بما قُبِل لا بما كُتِب.
* 🧭 بوابة `/r` للتوجيه الداخلي الآمن، و`404` أنيقة، وفحصا `/health` و`/health/nojs`.

## 🔄 5. سير العمل وحالات الانتقال

```
ملاحظة:  مسودة ← قيد المراجعة ← مقبولة / مرفوضة ← إعادة إرسال ← قيد المراجعة
إرسالية: وصف + كتّاب ← قيد المراجعة ← مقبولة / مرفوضة (تبقى إرسالية أبداً)
تقرير:   مسودة ←→ منشورة (بشرط: مقبولةٌ واحدة من اليوم ذاته + محتوى معتمد غير متقادم)
ترجمة:   أصل ← مهمة خلفية ← ترجمة محفوظة ← عرض حسب اللغة
```

| من | إلى | الإجراء | المخول |
|---|---|---|---|
| `draft` | `pending` | 📨 إرسال | المالك فقط |
| `pending` | `accepted` | ✅ قبول | الكاتب فقط |
| `pending` | `rejected` | ❌ رفض مسبّب | الكاتب فقط |
| `rejected` | `pending` | ↩️ إعادة إرسال | المالك فقط |
| `accepted` | — | 🔒 نهائية | المعالج وحده |
| `draft` | `published` | 📢 نشر | الكاتب المالك بمحتوى معتمد |
| `published` | `draft` | 📥 سحب | الكاتب المالك |

التفصيل: [`docs/WORKFLOW.md`](./docs/WORKFLOW.md) · [`docs/SYSTEM.md`](./docs/SYSTEM.md) · [`docs/REPORTS.md`](./docs/REPORTS.md)

## 🏗️ 6. البنية التقنية — هندسةٌ كالبنيان المرصوص

* 🧱 الإطار `Laravel 13 + PHP 8.4 + Livewire 4 + Vite 8 + Tailwind 4` — وخدماتٌ مفصولة (`NoteService`، `ReportService`، `ReportEngine`، `TranslationService`، `LocalizedPresenter`) لا يعرف بعضُها فضولَ بعض.
* 🧬 فصلٌ صارم: الوثيقة للعين، وبيانات التشغيل (`generation_id`، الكثافة، القوالب) للقاعدة والسجلات.
* ⚡ أداءٌ مدروس: `unionAll + paginate(24)` وكاش الترجمات وكتابةٌ ذرية للسياق.
* 🌐 شبكيٌّ مستقل: `LAN + PWA` بلا سحابةٍ مدفوعة (Gemini اختياري مجاني).
* 📝 كل توليدٍ وترجمةٍ وعرضٍ مسطورٌ في السجل، وكل اعتمادٍ نسخةٌ مرقمة — كسجلِّ تدقيقٍ لا يمحوه الزمن.
* التفصيل: [`docs/ARCHITECTURE.md`](./docs/ARCHITECTURE.md)

## 🗄️ 7. قاعدة البيانات — ذاكرة المنظومة

```
users ──< notes ──< attachments
  │           │
  │           └──< report_note >── reports ──< report_revisions
  │                                   └──< report_sheet_renders
  │
  ├──< general_submissions ──< general_submission_attachments
  │         └──< general_submission_report_writer >── users(report_writer)
  │
  ├──< content_translations
  ├──< notifications
  ├──< push_subscriptions
  └──< notification_preferences
```

* 👥 `users`: اسمٌ فريد ودورٌ (`monitor|report_writer`) وهاتفٌ وصورةٌ ورقمٌ شخصي.
* 📝 `notes`: المالك والطابق والكاميرا والزمنان والحالة — وفهارس على كل مِفصَل بحث.
* 📎 المرفقات: مسار `UUID` ونوعٌ حقيقي وحجمٌ واسمٌ أصلي.
* 📄 `reports`: المؤلف والعنوان والمحتوى المركّب والملخص والتوصيات والمسودات الآلية ونمط التوليد والحالة والرؤية والتواريخ.
* 🌐 `content_translations`: (النوع + المعرف + الحقل + اللغة) مفتاحُ فرادةٍ مركّب.
* التفصيل: [`docs/DATABASE.md`](./docs/DATABASE.md)

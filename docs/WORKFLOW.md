# WORKFLOW.md

## آلة الحالة

```
مسودة (draft)
  ↓
قيد المراجعة (pending)
  ↓         ↓
مقبولة    مرفوضة
(accepted) (rejected)
              ↓
        قيد المراجعة
           (pending)
```

## الانتقالات المسموحة فقط

| من          | إلى         | الإجراء   | المستخدم   |
|-------------|-------------|-----------|------------|
| draft       | pending     | إرسال     | مالك فقط   |
| pending     | accepted    | قبول      | كاتب تقارير فقط |
| pending     | rejected    | رفض      | كاتب تقارير فقط |
| rejected    | pending     | إعادة إرسال | مالك فقط |

## الانتقالات غير المسموحة

- draft → accepted ❌
- draft → rejected ❌
- pending → draft ❌
- accepted → أي شيء ❌
- rejected → accepted ❌
- rejected → draft ❌

## تعديل

| الحالة   | المالك | آخرون | كاتب التقارير |
|----------|--------|-------|---------------|
| draft    | نعم    | لا    | لا            |
| pending  | نعم    | لا    | لا            |
| rejected | نعم    | لا    | لا            |
| accepted | لا     | لا    | لا            |

## حذف

| الحالة   | المالك | آخرون |
|----------|--------|-------|
| draft    | نعم    | لا    |
| pending  | لا     | لا    |
| rejected | لا     | لا    |
| accepted | لا     | لا    |

## تفاصيل الإرسال

1. `draft → pending`
2. المالك فقط
3. بيانات الملاحظة يجب أن تكون صالحة
4. تعيين `sent_at`
5. مسح حقول الرفض/المعالجة القديمة

## تفاصيل القبول

1. `pending → accepted`
2. كاتب التقارير فقط
3. تعيين `processed_by`
4. تعيين `processed_at`
5. الملاحظة تصبح ثابتة (لا تعديل)

## تفاصيل الرفض

1. `pending → rejected`
2. كاتب التقارير فقط
3. `rejection_reason` إجباري
4. تعيين `processed_by`
5. تعيين `processed_at`

## تفاصيل إعادة الإرسال

1. `rejected → pending`
2. المالك فقط
3. نفس رقم الملاحظة
4. قد يُصحح الملاحظة/المرفقات أولاً
5. تعيين `sent_at` جديد
6. مسح حقول المعالجة

## تنفيذ

جميع الانتقالات تتم عبر `NoteService` باستخدام معاملات (transactions) حيثما يلزم الضمان الذري.
التحقق من الانتقالات يحدث في المستويين:
1. Policy (التفويض الأساسي)
2. NoteService (قواعد العمل)

## التقارير اليومية (دورة مستقلة)

```
مسودة (draft) ⇄ منشورة (published)
```

| من | إلى | الشرط |
|----|-----|-------|
| draft | published | نشر: محتوى نهائي غير فارغ + ملاحظة مقبولة واحدة على الأقل من نفس اليوم |
| published | draft | سحب نشر (تعود مسودة) |

*   التقرير مرتبط بيوم تقويمي واحد عبر `notes.observed_at` — أي ملاحظة من يوم آخر مرفوضة من السيرفر.
*   `ai_draft_content` مسودة صياغة فقط ولا تُنشر أبدًا — النشر من `content` حصرًا.
*   تنفيذ: `ReportService` + `ReportPolicy` — التفاصيل الكاملة في `REPORTS.md`.

## الإرسالات العامة (منفصلة كليًا عن الملاحظات)

```
مراقب: إنشاء (وصف + كتّاب فقط) → إرسال → pending
كاتب معني: قبول → accepted | رفض + سبب → rejected
```

*   القبول **يقلب الحالة فقط** — لا ينشئ `Note` أبدًا (الإرسالات ليست ملاحظات).
*   `notes.general_submission_id` عمود أرشيفي للفصل العرضي (قوائم الملاحظات تستبعد أي أثر إرسالات).
*   تنفيذ: `GeneralSubmissionService` + `GeneralSubmissionPolicy`.
